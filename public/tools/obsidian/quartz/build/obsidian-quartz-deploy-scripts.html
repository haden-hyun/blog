원클릭 배포 스크립트 구축

Sep 13, 202631 min read

  • tools/obsidian

Summary

  • 배포 로직은 Shell Commands 입력란에 인라인으로 넣지 않고 셸 스크립트 3종(Preview / Quick Publish / Clean Publish)으로 분리한다.
  • 스크립트가 자기 위치 기준으로 프로젝트 경로를 스스로 계산하므로, Shell Commands 쪽에는 호출 한 줄만 넣으면 된다.
  • v5에서는 빌드 전에 npx quartz plugin install이 반드시 선행한다. 로컬·원격 플러그인이 설치돼 있어야 빌드가 컴포넌트를 찾는다.
  • 빈 커밋 방지(git diff --cached --quiet), 안전한 push(--force-with-lease), 단계별 종료 코드와 로그로 실패 지점을 바로 파악한다.
  • Output 채널을 Notification balloon, 핸들링 모드를 Realtime으로 둬야 시작·결과 알림이 제때 뜬다.

실습 환경

이 시리즈는 macOS 기준으로 작성했다. 스크립트의 Homebrew 경로(/opt/homebrew/bin), lsof·open 명령, 단축키가 Windows와 다르므로 각자 환경에 맞게 바꿔 읽어야 한다. 이 글은 Quartz v5 기준이다.

들어가며

Cloudflare Pages 빌드 설정과 도메인 통합에서 Cloudflare가 빌드를 시도하지 않도록 만들었다. 이제 터미널을 열지 않고 옵시디언 안에서 단축키 하나로 배포하는 시스템을 만든다.

배포 로직은 Shell Commands 입력란이 아니라 셸 스크립트 파일에 둔다. 처음에는 긴 명령어를 Shell Commands에 직접 붙여넣어 썼지만, 다음 문제를 겪었다.

배포 로직은 Shell Commands 입력란이 아니라 셸 스크립트 파일에 둔다. 처음에는 긴 명령어를 Shell Commands에 직접 붙여넣어 썼지만, 다음 문제를 겪었다.

  • 디버깅 어려움: 출력을 숨기면(> /dev/null) 실패 원인을 알 수 없고, 숨기지 않으면 알림창이 도배됐다.
  • 관리·재사용 곤란: 세 명령에 export PATH, cd 같은 공통 코드가 중복됐다.
  • 환경 차이로 인한 실패: 옵시디언(GUI 앱)이 실행하는 셸은 터미널과 환경이 달라, 인라인 명령이 예기치 않게 중간에 끊겼다(특히 commit/push 단계).

  • 관리·재사용 곤란: 세 명령에 export PATH, cd 같은 공통 코드가 중복됐다.

  2. 필요하면 Cloudflare 캐시를 삭제한다(Caching → Configuration → Purge Everything).

  3. Clean Publish(Ctrl + Shift + L)로 캐시까지 지우고 재배포한다.

  4. Cloudflare 대시보드에서 배포 상태를 확인한다.

  5. 필요하면 Cloudflare 캐시를 삭제한다(Caching → Configuration → Purge Everything).
